# آماده‌سازی مینی‌اپ تلگرام R&MA بدون سرور اختصاصی

این راهنما برای آماده‌سازی رابط Mini App است تا بعداً فقط با تنظیم نشانی بک‌اند، به سرور اختصاصی WireGuard متصل شود.

## وضعیت و محدوده

- داشبورد اصلی در `frontend/index.html` حفظ شده است.
- SDK رسمی Telegram Web Apps در صفحه بارگذاری می‌شود.
- کلاینت API در `frontend/rma-api.js` فقط برای تبادل اولیه، `Telegram.WebApp.initData` را به بک‌اند می‌فرستد؛ پس از آن درخواست‌های خصوصی با Bearer session ارسال می‌شوند. Bot Token و کلید مشتق‌سازی نشست هرگز در مرورگر قرار نمی‌گیرند.
- دو Cloudflare Pages Function برای مسیرهای `/api/*` و `/health` اضافه شده‌اند تا در آینده درخواست‌ها را هم‌مبدأ به بک‌اند منتقل کنند.
- تا وقتی `BACKEND_ORIGIN` تنظیم نشده باشد، این توابع پاسخ 503 با پیام «بک‌اند هنوز راه‌اندازی نشده» می‌دهند؛ هیچ کانفیگ آزمایشی به‌عنوان کانفیگ واقعی ارائه نمی‌شود.
- این تغییرات به معنی انتشار عمومی، ساخت ربات تلگرام، یا راه‌اندازی VPN نیست.
- بخش‌های انتخاب کشور/سرور، پینگ، پروتکل‌های VLESS و NapsternetV، پلن‌ها، قیمت‌ها، دعوت دوستان و پرداخت در داشبورد فعلاً صرفاً نمایشی‌اند؛ دکمه‌های خرید و پیشنهاد کانفیگ شبکه‌های اجتماعی غیرفعال شده‌اند تا زمان پیاده‌سازی و آزمون واقعی.

## انتشار رایگان رابط کاربری روی Cloudflare Pages

1. وارد حساب Cloudflare شو و از Workers & Pages یک Pages project بساز.
2. مخزن GitHub آزمایشی `vahid250/azmayesh` را انتخاب کن.
3. شاخه انتشار را `work/rma-backend-dashboard` انتخاب کن.
4. مقدار Root directory را `frontend` قرار بده.
5. مقدار Build command را خالی و Build output directory را `.` قرار بده؛ مسیر خروجی نسبت به Root directory محاسبه می‌شود.
6. پس از انتشار، Cloudflare یک نشانی HTTPS می‌دهد. تا پیش از اتصال بک‌اند، بازشدن صفحه فقط رابط کاربری را تأیید می‌کند.

## اتصال آینده بک‌اند

در تنظیمات Pages، متغیر محیطی زیر را فقط پس از راه‌اندازی بک‌اند واقعی تعریف کن:

- `BACKEND_ORIGIN`: فقط origin سرویس FastAPI، مانند `https://api.example.com`؛ بدون مسیر، query یا slash انتهایی.

این مقدار باید یک نشانی HTTPS باشد. توابع Pages مسیرهای `/api/*` و `/health` را به همان مسیر در بک‌اند می‌فرستند. در نتیجه API فعلی FastAPI که مسیرهای `/api/v1/...` و `/health` دارد با این proxy هم‌خوان است.

توکن ربات، کلید رمزنگاری، کلید خصوصی WireGuard و سایر اسرار را در متغیرهای محیطی/Secrets سرویس بک‌اند نگه دار؛ آن‌ها را در GitHub، HTML، JavaScript یا تنظیمات عمومی Pages قرار نده.

## اتصال Mini App به ربات تلگرام

پس از داشتن یک ربات معتبر و URL عمومی HTTPS:

1. نام کاربری دقیق ربات را در BotFather بررسی کن.
2. در تنظیمات Mini App یا Menu Button، URL منتشرشده Cloudflare Pages را ثبت کن.
3. Mini App را از داخل همان ربات باز کن؛ بازکردن URL در مرورگر معمولی، جای آزمون Telegram WebApp را نمی‌گیرد.
4. در آزمون داخل تلگرام، وجود `Telegram.WebApp.initData` و ارسال موفق آن به بک‌اند را بررسی کن.

تا وقتی ربات معتبر، Bot Token و کلید مستقل نشست در Secret امن، دیتابیس مهاجرت‌یافته و بک‌اند در دسترس نباشند، ورود احرازشده و APIهای کاربری در محیط واقعی قابل تأیید نیستند. تغییرات فعلی هنوز deploy نشده‌اند و migration روی دیتابیس اصلی اجرا نشده است.

## معیارهای آماده‌بودن پیش از اتصال سرور اختصاصی

- [ ] انتشار HTTPS داشبورد و بارگذاری صحیح در Telegram WebView
- [ ] بازشدن Mini App از منوی ربات واقعی
- [ ] اعتبارسنجی سمت سرور Telegram initData با Bot Token نگهداری‌شده در Secret
- [ ] تبادل initData با نشست مستقل Bearer و تنظیم راز SESSION_DERIVATION_KEY / RMA_SESSION_DERIVATION_KEY
- [ ] تنظیم Cloudflare Rate Limiting/WAF برای مسیر تبادل نشست و عملیات حساس
- [ ] ذخیره پایدار کاربران و داده‌ها در دیتابیس مناسب
- [ ] محدودسازی دسترسی هر کاربر به داده‌های خودش
- [ ] اتصال هم‌مبدأ Pages Functions به FastAPI
- [ ] نمایش وضعیت «سرور VPN هنوز متصل نشده» و غیرفعال بودن صدور واقعی
- [ ] آزمون امنیتی و end-to-end پس از اتصال VPS

## محدودیت مهم

Cloudflare Pages میزبانی رابط کاربری و توابع سبک HTTP را فراهم می‌کند؛ جای VPS لینوکسی با دسترسی مدیریتی، رابط WireGuard، UDP، IP forwarding و NAT را نمی‌گیرد. تولید کانفیگ قابل اتصال و عبور اینترنت تا راه‌اندازی و آزمون سرور واقعی غیرفعال می‌ماند.


## آماده‌سازی بک‌اند FastAPI روی Render و پایگاه‌داده Neon

فایل `render.yaml` در ریشه مخزن، یک Blueprint برای سرویس آزمایشی تعریف می‌کند:

- شاخهٔ انتخاب‌شده: `work/rma-backend-dashboard` (نه شاخه اصلی)
- پوشه سرویس: `backend`
- محیط اجرا: Python
- دستور ساخت: `pip install -r requirements.txt`
- دستور اجرا: `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT` (ابتدا مهاجرت‌های دیتابیس اجرا می‌شوند)
- مسیر بررسی سلامت: `/health`
- پلن پیشنهادی: Free
- انتشار خودکار فقط پس از موفقیت بررسی‌های CI فعال است (`autoDeployTrigger: checksPass`)؛ بنابراین commit ناموفق نباید به سرویس آزمایشی منتشر شود.
- حالت VPN: عمداً `MOCK_MODE=true`

### ۱) ساخت پایگاه‌داده Neon

1. در Neon یک حساب و پروژه PostgreSQL بساز.
2. منطقه جغرافیایی دیتابیس را تا حد امکان نزدیک منطقه سرویس Render انتخاب کن.
3. از بخش اتصال، گزینه Pooled connection را انتخاب کن و رشته اتصال PostgreSQL را کپی کن.
4. رشته اتصال محرمانه است؛ آن را فقط در فیلد `DATABASE_URL` در تنظیمات Render قرار بده، نه در GitHub یا گفت‌وگو.
5. کد بک‌اند پیشوندهای `postgres://` و `postgresql://` را به درایور نصب‌شده psycopg 3 تبدیل می‌کند. پارامترهای SSL رشته اتصال حفظ می‌شوند.

### ۲) ساخت سرویس Render از روی Blueprint

1. وارد Render شو و گزینه New Blueprint را انتخاب کن.
2. مخزن `vahid250/azmayesh` را متصل کن.
3. فایل `render.yaml` در ریشه مخزن را انتخاب کن.
4. پیش از تأیید، بررسی کن که Branch همان `work/rma-backend-dashboard` و پلن سرویس Free باشد.
5. مقادیر محرمانه را فقط در فرم امن Render وارد کن:
   - `DATABASE_URL`: رشته اتصال Pooled از Neon
   - `ENCRYPTION_KEY`: کلید Fernet تولیدشده با دستور زیر
   - `TELEGRAM_BOT_TOKEN`: توکن ربات موجود
   - `TELEGRAM_WEBHOOK_SECRET`: یک مقدار تصادفی مستقل برای webhook
   - `SESSION_DERIVATION_KEY`: یک راز تصادفی مستقل حداقل ۳۲ بایتی برای صدور نشست؛ با Bot Token و ENCRYPTION_KEY متفاوت باشد و در گفت‌وگو یا Git قرار نگیرد.
   - `MINI_APP_URL`: در این مرحله در Blueprint تعریف نشده است؛ پس از انتشار HTTPS فرانت‌اند، آن را دستی در تنظیمات محیطی سرویس اضافه کن.
6. کلید Fernet را روی دستگاه خودت تولید کن؛ آن را در چت ارسال نکن:
   ```bash
   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```
7. اگر Render برای ایجاد حساب، تأیید هویت یا روش پرداخت درخواست اضافه‌ای نشان داد، پیش از ادامه متوقف شو و شرایط را بررسی کن. این فایل هیچ پرداخت یا استقراری را خودکار انجام نمی‌دهد.

### ۳) متغیرهای مهم و حالت امن آغازین

- `APP_ENV=production`: مسیر کلید آزمایشی API را غیرفعال نگه می‌دارد.
- `MOCK_MODE=true`: خروجی WireGuard فقط آزمایشی است و به سرور واقعی وصل نمی‌شود.
- `TELEGRAM_INIT_DATA_MAX_AGE_SECONDS=3600`: داده ورود تلگرام حداکثر یک ساعت اعتبار دارد.
- `DATABASE_URL`: باید به PostgreSQL پایدار Neon اشاره کند؛ از SQLite محلی Render برای داده کاربران استفاده نکن.
- `ENCRYPTION_KEY`: برای رمزنگاری کلید خصوصی و متن کانفیگ ذخیره‌شده لازم است. اگر این کلید عوض شود، داده‌های رمز‌شده قبلی قابل رمزگشایی نخواهند بود؛ آن را امن پشتیبان بگیر.

### ۴) آزمون پس از استقرار

پس از پایان Deploy، آدرس HTTPS سرویس Render را با مسیر `/health` باز کن. در وضعیت اولیه باید پاسخ سلامت نشان دهد:

- `status=ok`
- `mock_mode=true`
- `real_provisioning_configured=false`
- `connectivity_verified=false`

این پاسخ فقط سلامت اجرای API را نشان می‌دهد، نه اتصال VPN یا اینترنت کاربر. سپس باید اتصال دیتابیس، ورود واقعی Mini App و ارتباط Pages proxy را جداگانه آزمایش کنیم.

### ۵) محدودیت‌های پلن رایگان

سرویس وب رایگان Render پس از دوره بی‌کاری متوقف می‌شود و درخواست بعدی ممکن است با تأخیر راه‌اندازی شود. پلن رایگان دیسک پایدار ندارد؛ به همین دلیل این طرح از Neon PostgreSQL برای داده‌های ماندگار استفاده می‌کند. برای کاربری دائمی، تأخیر بیدارشدن و محدودیت منابع باید در آزمون واقعی سنجیده شود.

مرجع رسمی ساختار Blueprint و متغیرهای محرمانه: https://render.com/docs/blueprint-spec
مرجع رسمی اتصال Neon و انتخاب رشته اتصال pooled: https://neon.com/docs/connect/connect-from-any-app


## آماده‌سازی رایگان فرانت‌اند روی Cloudflare Pages

پوشه `frontend` یک سایت استاتیک HTML/JavaScript است و نیاز به مرحله build ندارد. فایل `frontend/wrangler.toml` تنظیمات Pages را مشخص می‌کند:

- نام پیشنهادی پروژه: `rma-miniapp`
- پوشه خروجی: `.` (همان پوشه frontend)
- تاریخ سازگاری Functions: `2026-11-15`
- مسیرهای Function در `frontend/functions/` قرار دارند و باید همراه سایت منتشر شوند.

### تنظیم از طریق Git integration

1. در Cloudflare وارد بخش Workers & Pages شو و Create application / Pages را انتخاب کن.
2. اگر حساب رایگان بدون درخواست کارت یا پرداخت قابل ساخت بود، GitHub را متصل کن و مخزن `vahid250/azmayesh` را انتخاب کن.
3. شاخهٔ `work/rma-backend-dashboard` را برای انتشار آزمایشی انتخاب کن؛ شاخه اصلی را تغییر نده.
4. Root directory را `frontend` قرار بده.
5. چون سایت استاتیک است، Build command را خالی بگذار و خروجی را `.` قرار بده. فایل `wrangler.toml` هم این مقادیر را در مخزن ثبت کرده است.
6. اگر صفحه تنظیمات برای Build command مقدار اجباری خواست، متوقف شو و قبل از تغییر آن، تصویر صفحه را بررسی می‌کنیم؛ دستور ساخت ساختگی وارد نکن.
7. تا زمان آماده‌شدن API، متغیر محیطی `BACKEND_ORIGIN` را تنظیم نکن. Functionهای `/api/*` و `/health` در این حالت پاسخ کنترل‌شده 503 می‌دهند؛ این رفتار عمدی است.
8. بعد از انتشار موفق، آدرس HTTPS تولیدشده را نگه دار. هنوز آن را به BotFather یا `MINI_APP_URL` وصل نکن؛ ابتدا بک‌اند و پراکسی را با هم آزمایش می‌کنیم.

**قانون توقف هزینه:** اگر Cloudflare هنگام ساخت حساب، اتصال GitHub یا انتشار آزمایشی درخواست کارت بانکی، پرداخت یا ارتقای پولی کرد، هیچ اطلاعات پرداختی وارد نکن و ادامه نده. از صفحه خارج شو و گزینه رایگان جایگزین را بررسی می‌کنیم. هیچ ثبت‌نام یا استقراری از طرف این مخزن به‌صورت خودکار انجام نمی‌شود.

### آزمون محلی بدون حساب Cloudflare

در رایانه‌ای که Node.js نصب است، می‌توان Wrangler را فقط برای توسعه محلی اجرا کرد:

```bash
cd frontend
npx wrangler pages dev .
```

برای آزمون Functionهای پراکسی، متغیر آزمایشی `BACKEND_ORIGIN` باید به یک API HTTPS آزمایشی تحت کنترل خودتان اشاره کند. توکن ربات، کلید رمزنگاری و کلید خصوصی WireGuard را هرگز به محیط فرانت‌اند یا فایل Wrangler اضافه نکنید.

مستندات رسمی: https://developers.cloudflare.com/pages/functions/wrangler-configuration/
راهنمای رسمی Pages Functions: https://developers.cloudflare.com/pages/functions/get-started/
